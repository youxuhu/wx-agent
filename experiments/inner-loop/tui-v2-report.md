# TUI 接入第二阶段（2026-11-03）

用户最新范围：只在 TUI 实现与测试，不处理 GUI。本轮未提交的 Web 源码及构建产物已全部撤回；没有打包、重装或重启用户桌面应用。

## 已完成

- 默认 off；保留原手动 shadow，新增 auto（材料变化驱动 shadow）及 capture on/off（明确选择之后的短消息和普通回复片段）。只在用户来源的工作真正 settled 后探索，无 timer 点火、无自激、无模型工具调用。
- 新候选表达规则独立于冻结研究：跟随材料语言、具体联系、温和推断、避免强行追问、复述和虚构情绪。普通判断仍为默认，不把锚定评分当人类偏好。
- 自动 shadow 不直接往会话插话，只保留内存候选。prepare/show/say 提供可查看、用户明确确认的一次发送；确认后关闭授权。唯一 deliveryId 防重放，并只读本次新追加字节确认落盘，避免把 sendMessage 的 void 返回当成功。
- 输入取消、过期上下文、会话/树/重载失效；新事件等待旧取消请求收尾，只处理最新有效事件，避免同时占用预算锁。不重试沉默、非法输出或未知费用请求。

## 验证及其边界

真实 SDK 隔离会话使用受控推理验证：默认 off、材料选择、事件驱动、无重复轮询、custom 输出不点火、忽略 thinking、输入取消、确认后落盘、重放拒绝、取消请求串行收尾及 reload 清空授权。

真实交互式 Pi 1.4.0 在 PTY 中实际输入 `/inner-loop shadow/add/prepare/say`，regular 与 fullscreen 模式均验证；没有 GUI 操作参与这条最终测试。默认离线终端测试还实际键入字符，确认中断候选且不多发消息。

真实模型终端验证只做一轮新增两调用（生成 + 普通判断），使用原批准的 DeepSeek 路由和累计账本。输出为：“雨水收集可以很自然地融入庭院设计——屋顶或棚架的落水管能直接接入种植区旁的储水罐。” 在真实 TUI 确认发送后，JSONL 重开包含恰好一条 approved 消息；重复 say 被拒绝，主会话模型调用为零。

最终检查：全量 `scripts/test.py` 通过；真实 fullscreen PTY 离线回归通过；固定版本 LSP 对研究及接入共 15 个模块零诊断；公开证据离线复算一致。最终 Git diff 不含任何 piwebui 文件，机器设置和上一轮 token-confidence 研究均排除提交。

这仅证明实际终端接入与表达语言可工作，不证明“更像人”已获用户认可，也不代表自主创造性或真实心理动机。原 15 条候选的人工标签保持空白，没有代理填写用户满意度。

## 保留的限制

TUI 的公开扩展 API 无可靠的窗口焦点/连接信号；fullscreen 提前消费焦点及部分滚动事件。因此本阶段没有无人确认的 active 自动发言，使用当前 say 命令确认一次发送。它不是 GUI 审批，也不需要用户重新授权开发工作，而是 TUI 功能自身的当前注意力确认入口。

空会话首次落盘问题仍遵循 SDK 语义；say 要求已有保存记录及 assistant 消息，不用伪造消息解决。后续材料只保留有限片段，可能缺上下文；过长请求停止，不能宣称可无损理解整段真实聊天。

累计保守账本：80 次、33,826 tokens / US$0.0303072；原总上限 192 次、500,000 tokens、US$1 不变。计数包含撤回前发生的两次接入请求，费用不重置。冻结 48 场景没有重跑、原源码/数据未改；开发默认模型和机器配置未修改。
